## OQ-C1：`scope` 字段纳入 authority 模型

### 状态

```text
APPROVED — A
```

### 正式决策

1. `scope` 正式纳入 authority 模型，成为 `authorities.json` 中每条 authority 的正式字段。
2. 值域固定为两个：

```text
scope ∈ {
  feature-level,
  historical-background
}
```

3. Relation rule 的 `authorityId` 只能引用 `scope = feature-level` 的 authority。
4. `scope = historical-background` 的 authority 允许存在于注册表，但**不得**作为任何 rule 的 output 目标。
5. `auth:ALLIED-CONTROL-COUNCIL` 保留为 `historical-background`，不得被规则引用。
6. 当前暂不执行工程修改；将来执行时，涉及：

   * `docs/design/P4.1-A-design.md`（新增 `scope` 字段定义）
   * `scripts/lib/relations.mjs`（`validateAuthorities` 加 scope 校验；`validateRules` 拒绝引用 `historical-background`）
   * `tests/relations/**`（新增：规则引用背景类 authority → 构建失败）
   * **不修改** Batch 1 已封板的 6 条规则
   * **不重写** 54 个 sidecar

### 不涉及

* 不修改 `relations.json`
* 当前实现中已有 `scope` 数据，但 OQ-C1 批准将 `scope` 正式纳入冻结设计，并增加相应 validator 约束。
* 不新增 relationship enum
* 不新增 namespace

## OQ-C5：`sovereignId` 语义

### 状态

```text
APPROVED — A
```

### 正式决策

`sovereignId` 与 `authorityId` 的正式语义为：

```text
sovereignId = 法理/法律上的主权归属
authorityId = 实际行使控制、行政或军事管理权力的主体
```

### Occupation 的目标语义

对 `relationship = occupied` 的场景，目标语义为：

```text
entityId     = 被占领政治实体
sovereignId  = 被占领政治实体的法理主权者
authorityId  = 占领/军事管理当局
relationship = occupied
```

举例（目标语义，非当前实现）：

```text
1945 Japan under US occupation
entityId     = JP-JAPAN
sovereignId  = JP-JAPAN
authorityId  = auth:SCAP
relationship = occupied
```

```text
1941–1952 Eritrea under British Military Administration
entityId     = ER-ERITREA
sovereignId  = 意大利对应的现有 polity entityId（待项目实体注册表确认）
authorityId  = auth:UK-BMA
relationship = occupied
```

> 说明：Eritrea 1941–1952 的法理主权归属应按历史裁决研究指向意大利，但具体 `sovereignId` 必须从项目现有实体注册表中确认。当前草案中不得将尚未确认存在的 entityId（例如 `IT-ITALY`）写成既定项目 ID。

### 记录

1. **§7 保持原文**，不需要修改。方案 A + occupation 目标语义正好满足 §7 的字面要求（`occupied ⇒ sovereignId 非空`）。
2. **Batch 1 保持封板**，不回滚、不修改。
3. Batch 1 当前的 `sovereignId = null` **不构成新的永久语义**。它是"语义未冻结时的保守结果"，仅对 Batch 1 有效。
4. 将来重新处理同一时间断面时，应按 C5 新语义重新裁定。这需要单独的授权。

### 不涉及

* 不修改 P4.1-A v3
* 不修改 relations.json
* 不修改 authorities.json
* 不修改 sidecar
* 不修改 entityId / color
* 不新增字段

## `sovereignId = null` 的语义边界

### 正式记录

```text
null + resolutionStatus = unresolved
= 当前无法确定 sovereignId
  （resolver 未命中规则，或证据不足）

null + resolutionStatus = resolved
= 已经完成历史裁定，
  但当前单值 schema 无法表达一个合法的单一 sovereignId
  （例如多主权者、无主地）
```

### 关键区别

* 两者靠**已有的** `resolutionStatus` 字段区分。
* **不新增字段**即可表达。
* **不新增 relationship enum**。
* **不新增 namespace**。

### 隐含约束

* `null + resolved` 不应与 `relationship = occupied` 同时出现（违反 §7）。
* 其他 relationship 下是否允许 `null + resolved`，见"后续 OPEN 项 C5-D1"。

## OQ-4 ~ OQ-8 表达力缺口裁定

### OQ-4：联邦（Federation）

状态：OPEN

正式裁定：
- 现有 11 个 relationship 枚举无法表达 federation
- 明确禁止使用 autonomous 替代
- 相关案例（Eritrea 1952–1962）保持 unresolved
- 等 identity 层或 ontology 层扩展时再处理

### OQ-5：自治领（Dominion）

状态：APPROVED

正式裁定：
- 使用 autonomous
- 目标语义：autonomous + sovereignId（母国）+ authorityId（自治领 polity）
- 例如：加拿大 1867 起 → autonomous / GB-UNITED-KINGDOM / CA-CANADA

### OQ-6：个人联合（Personal Union）

状态：OPEN

正式裁定：
- 现有 11 个 relationship 枚举无法表达 personal-union
- 暂不新增枚举
- 相关案例（英格兰-苏格兰 1603–1707 等）按 unresolved 处理
- 共享君主的事实保留在历史裁决报告，不进入关系层

### OQ-7：特许（Chartered）

状态：APPROVED

正式裁定：
- 使用 administered
- 目标语义：administered + sovereignId（主权者）+ authorityId（特许实体）
- 例如：英属东印度公司 → administered / GB-UNITED-KINGDOM / auth:BEIC
- 注意：此映射不解除 administered 枚举本身的 OPEN 状态
  （非特许类 administered 仍受 C5-D1 约束）

### OQ-8：多主权者 / 重叠声索

状态：APPROVED（分类别）

正式裁定：
- 真正共管（如 Anglo-Egyptian Sudan）→ condominium
- 重叠声索（如 Kuril Islands）→ unknown
- 重叠声索不得伪装成 condominium

## 后续 OPEN 项

### C5-D1：`null + resolved` 与各 relationship 的兼容范围

**状态**：`OPEN`

**问题**：哪些 relationship 允许 `null + resolved`（即已裁定但无单一 sovereignId）。

**概念上的初步倾向**（**未冻结**，仅记录）：

可能允许：

* `condominium`（多主权者，单值无法表达）
* `unknown`（确实未定）
* 无主地类场景

可能不允许：

* `occupied`
* `colony`
* `protectorate`
* `sovereign-territory`

**处理时机**：建议在正式进入 Batch 2 前明确。

### C5-D2：是否机器化 relationship → sovereignId 约束

**状态**：`OPEN`

**问题**：是否需要在未来的 validator 中，把 C5 及 C5-D1 确定的关系约束机器化。

例如：

* `occupied` 时强制 `sovereignId ≠ null`
* `sovereign-territory` 时强制 `sovereignId = entityId`
* `condominium` 时允许 `sovereignId = null + resolved`

**处理时机**：与 C5-D1 一起裁定，或在首次实现 validator 扩展时裁定。
