## 1. 一个必须先讲清楚的硬限制

`overrides.mergeRuns` 只能把**同一个 normalized key 的多个 run 合并成一个实体**。

它**无法**把两个不同的 key 认成同一个政权。而本项目里最严重的几次"同一国家多个颜色"，恰恰是跨 key 的：

| 国家 | 实际用到的 key | 年份 |
|---|---|---|
| 英国 | `united kingdom` / `united kingdom of great britain and ireland` / `great britain` / `england and ireland` | 1530 – 2010 |
| 美国 | `united states of america` / `united states` | 1783 – 2010 |
| 丹麦 | `denmark` / `denmark-norway` | 1100 – 2010 |
| 挪威 | `norway` / `denmark-norway` / `sweden-norway` | 1100 – 2010 |
| 瑞典 | `sweden` / `sweden-norway` | 1000 – 2010 |

**所以：即使把 `mergeRuns` 全部写对，英国在 1914 年仍然会是 2 种颜色、1878–1938 年每年都是 2 种颜色。** 见第 5 节。

## 2. 自动判定的可靠性（请勿整批照抄 A 类）

清单里的 A/B/C 是**机械规则**（token 集合包含 → 0.90 / Jaccard / 拼写相似度），不等于史实。实测它的两类错误：

**① A 类会误判"不同政权"为"建议合并"**

| key | 3 个 run | 为什么是误判 |
|---|---|---|
| `poland` | 1000–1300 / 1783 / 1920–2010 | 皮雅斯特王朝、瓜分期的残余、第二共和国——三个不同政权 |
| `ghana` | 800–1200 / 1920–1930 / 1960–2010 | 加纳帝国、黄金海岸、加纳共和国 |
| `serbia` | 900–1279 / 1878–1914 / 1994–2010 | 中世纪塞尔维亚、塞尔维亚王国、现代塞尔维亚 |
| `hindu kingdoms` | -500–700 / 1100 / 1700–1715 | 本身就是集合名词，不是单一政权 |

误判来源：缺口年份里恰好有 `poland-lithuania`（含 `poland`）、`ghan…` 之类 token 包含关系的 key。**规则把"名字像"当成了"政权同"。**

**② 短国名的拼写相似度是纯噪声**

- `uganda` 的候选被匹配成 `rwanda`（0.67 拼写）
- `zambia` 的候选被匹配成 `namibia`（0.71 拼写）

**结论：清单第 3 节的"近似 key"列只当线索，下面三档才是建议。**

## 4. 我建议的 `mergeRuns` 三档

### 4.1 T1 — 建议合并（高置信，14 条）

共同特征：**缺口恰好是 `1938, 1945` 两个快照**（即 1930 → 1960，上游在二战前后漏记了这些国家），run 的两端是同一块territory的殖民时期与独立后。

```json
"mergeRuns": [
  "uganda", "zambia", "algeria", "nigeria", "swaziland",
  "botswana", "eritrea", "kenya", "lesotho", "mozambique",
  "sierra leone", "tanzania, united republic of", "zimbabwe",
  "united states virgin islands"
]
```

（前 5 个来自自动判定的 A 类，后 9 个来自 B 类；`united states virgin islands` 的缺口是 1945/1960，同一属地。）

### 4.2 T2 — 倾向合并，但要你拍板（20 条，分两组）

**T2a 同一国家，缺口是上游缺数据（12 条）**

```json
"mergeRuns": [
  "united states", "united kingdom", "denmark", "norway",
  "denmark-norway", "sweden", "austria", "oman", "rwanda",
  "greenland", "angola", "madagascar"
]
```

> 每条的风险：`angola` 的 run #0 只有 1815 年 1 个 feature；`madagascar` 的 run #0 是 1000–1900（18 个 feature，其实是多个马尔加什政权共用一个 key）；`greenland` 的 run #0 只有 1900 年。若你认为这些不算"同一政权"，把它们移到 T3 即可。

**T2b 同一族群 / 考古文化（非国家，8 条）**

```json
"mergeRuns": [
  "ainu", "beothuk", "eastern north american hunter-gatherers",
  "pagan", "pandya state", "mon state", "pyu state",
  "sinhalese kingdoms"
]
```

> 这些 key 本身就是族群名或王朝名，同一 key 的断开基本是上游快照覆盖不均。注意 `maori` 与 `māori` 是**两个不同的 key**（弯音差异），P4.1 第 1 步已判定不能盲目折叠变音，所以它们各自都会被合并，但**彼此之间仍不会同色**。

### 4.3 T3 — 建议**不**合并

**跨政权的（10 条）**：`poland`、`serbia`、`ghana`、`croatia`、`hungary`、`cambodia`、`somalia`、`hindu kingdoms`、`maori`/`māori` 之外的历史集合名词、以及 `malays`、`multan`、`sindh`、`thai`、`maize farmers`（跨度 200–2,000 年，且多为族群/文化名）。

**C 类 33 条全部保持切分**：`bhutan`、`yemen`、`cyprus`、`guanches`、`nepal`、`tuʻi tonga empire`、`papal states`、`papua new guinea`、`korea`、`hadramaut`、`hainan`、`dorset`、`orissa`、`annam`、`paleo-inuit`、`papuans`、`scythians`、`georgia`、`hejaz`、`moldova`、`tungus`、`xiongnu`、`aboriginal tasmanians`、`arabs`、`funj`、`kalinga`、`berbers`、`kamarupa`、`magadha`、`poverty point culture`、`samis`、`sind`、`yayoi`。

## 5. 比 `mergeRuns` 更要紧的 4 个结构性问题

### 5.1 英国：同一年里 2–3 种颜色（最严重）

实测各年 key → entityId：

| 年 | `united kingdom` | `united kingdom of great britain and ireland` | 其它 |
|---|---|---|---|
| 1715 | ×9 → `auto:united kingdom` | — | — |
| 1783 / 1800 | **完全不存在（上游无英国条目）** | — | — |
| 1815 | ×1 → `auto:united kingdom#1` | ×2 → `auto:united kingdom of great britain and ireland` | `england and ireland`(1530) 又是另一个 key |
| 1914 | ×2 → `auto:united kingdom#1` | ×12 → `auto:united kingdom of great britain and ireland` | — |
| 1920 | ×2 → `auto:united kingdom#1` | ×9 → `auto:united kingdom of great britain and ireland` | — |
| 1960 | ×2 → `auto:united kingdom#1` | — | — |

→ **同一个国家在同一年被画成 2 种颜色**，且 1783/1800 完全没有。`mergeRuns` 修不了。

**建议**：建一个手工实体（例如 `GB-UK`，label "英国 / United Kingdom"），`keys` 同时列 `united kingdom`、`united kingdom of great britain and ireland`、`great britain`、`england and ireland`，`periods: [[1707, 2010]]`。

### 5.2 美国：两个 key

`united states of america`（1783–1900）与 `united states`（1815、1914–2010）是同一个国家。

**建议**：手工实体 `US-USA`，`keys: ["united states", "united states of america"]`，`periods: [[1776, 2010]]`。
（注意 1815 年两个 key 是否会同年共现，实施时要单独确认；同年共现则同年同色，可接受。）

### 5.3 丹麦 / 挪威 / 瑞典：联合王国是独立 key

`denmark-norway`（1492–1800 共 13 个 feature）与 `sweden-norway`（1815 等）在上游是独立政权 key。

**建议**：不要用 `mergeRuns` 去硬合。要么接受"丹麦-挪威联合王国"是独立实体（我认为这在史学上是成立的），要么为丹麦建手工实体时把 `denmark-norway` 也列进 `keys` 并给 `periods`。**这是历史判断，需要你定。**

### 5.4 `Japan` key 被切成 4 段

| run | 年份 | entityId |
|---|---|---|
| #0 | 800 | `auto:japan` |
| #1 | 1492–1500 | `auto:japan#1` |
| #2 | 1783–1815 | `auto:japan#2` |
| #3 | 1960–2010 | `JP-MODERN` |

→ "不同历史时期用不同颜色"符合你的原则，但**这里的分段是空档+`periods`落空的副产品，不是人工判断的结果**。建议要么显式补 3 个手工实体（平安/战国/江户），要么在文档里明确接受。

## 6. 我在 P4.1 实施里发现的一处真实缺陷

**`RU-USSR` 的 `periods` 是 `[[1922, 1991]]`，但上游在 1920 年就有 `USSR` 这个 key（4 个要素）。**

实测：

```
=== 1920 年 ===   ussr ×4  → auto:ussr        ← 落回自动实体
=== 1960 年 ===   ussr ×1  → RU-USSR
```

→ 结果是**苏联在 1920 年与 1930–1960 年颜色不同**，而这恰恰是 P4.1 最该修好的那类漂移。

**建议修正**：把 `RU-USSR.periods` 改为 `[[1920, 1991]]`（或 `[[1917, 1991]]`；1917 不是快照年，效果相同）。这是 1 行改动，属于我实施时的纪年取错，不是设计问题。
