## §2 判定规则（本方案的核心，必须与年份脱钩）

两个正交动作，规则都不含年份硬编码：

**A. 存在性（presence）** —— 一个年份是否「已有南极」：
> 存在任一 feature，其几何 bbox 的 `minLatitude <= ANTARCTIC_MAX_LATITUDE (-60)`，或归一化后的 `name|subject|partOf|abbrev` 任一等于 `antarctica`，或 `entityId === 'auto:antarctica'`。
> 若不存在 → 追加规范化南极要素。

**B. 身份归一（normalize）** —— 命中上述任一南极信号的 feature：
> 强制 `entityId = 'UNNAMED'`、`color = '#9aa0a6'`、`precision = 1`；`name/subject/partOf/abbrev` 保持原样（见 §8-D2）。

阈值 `-60°` 的依据：54 年全量扫描下，唯一跨过 −60° 的要素就是南极大陆与南极沿岸岛（南美最南要素 bbox minY = −55.05167，与之有 5° 安全间隔）。`auto:antarctica` 与 `antarctica` 文本规则覆盖「有名南极」，几何规则覆盖「无名南极」与「整块缺失」。

## §4 推荐方案（B）具体改动

### 4.1 新增文件（纯前端，均不在保护集内）

**① `src/data/geographic/antarcticaGeometry.ts`** —— 冻结的规范南极几何
- 内容：从 `public/data/years/world_2010.json` 中 `minY=-90` 的那个 UNNAMED 要素（1,091 点、bbox `[-180,-90,180,-63.24529]`、已 5 位量化）**原样搬出**为一个 `MultiPolygon` 常量。
- 导出：`export const ANTARCTICA_GEOMETRY: MultiPolygon`。
- 一致性理由：P4.4-2 已证产物坐标 = 由 raw 重推导的结果，因此这份几何与其余 52 年的南极**逐位相同**，注入后肉眼无差异。
- 体积：约 22 KB 原始文本（gzip 约 6–8 KB），进主 chunk。

**② `src/data/geographicOverlay.ts`** —— 纯函数（无副作用、可测试、幂等）
```ts
export const ANTARCTICA_ENTITY = 'UNNAMED';        // 与 scripts/lib/color.mjs 的 UNNAMED_ENTITY 同步
export const ANTARCTICA_COLOR = '#9aa0a6';         // 与 scripts/lib/color.mjs:35 的 UNNAMED_COLOR 同步
export const ANTARCTIC_MAX_LATITUDE = -60;

export function featureMinLatitude(geometry: MultiPolygon): number;
export function isAntarcticFeature(feature: HistFeature): boolean;
/** 幂等：返回新 FeatureCollection；非南极要素按原引用透传 */
export function applyGeographicOverlay(data: YearData): YearData;
```
行为：
1. `features.map(f => isAntarcticFeature(f) ? {...f, properties: {...f.properties, entityId: ANTARCTICA_ENTITY, color: ANTARCTICA_COLOR, precision: 1}} : f)`；
2. 若第 1 步结果中没有任何南极要素 → `features.push({ type:'Feature', id: data.features.length, properties:{ entityId:'UNNAMED', name:null, abbrev:null, subject:null, partOf:null, precision:1, color:'#9aa0a6' }, geometry: ANTARCTICA_GEOMETRY })`；
3. `return { ...data, features: next }`（spread 保留文件顶层 `name`）。

要点：追加要素的 `id = features.length`（= 原数组长度），与构建期「`id` 就是数组下标」的口径一致，**不与任何既有 id 冲突，也不改动既有 id** → relations sidecar 的按 id 查表完全不受影响。

### 4.2 修改文件（1 个，3 行级）

**③ `src/data/loadYear.ts`** —— 在唯一数据入口套一层（`:45` 校验之后、`:49 cache.set` 之前）
```ts
const parsed = (await res.json()) as YearData;
if (parsed?.type !== 'FeatureCollection' || !Array.isArray(parsed.features)) throw new Error(...);
const data = applyGeographicOverlay(parsed);   // 新增 1 行
cache.set(key, data);                          // 缓存的是已归一对象
```
- 为什么放这里而不是 `MapView.tsx`：`MapView` 有 **两处** `source.setData()`（`:168 applyPending()` 与 `:240` 年份 effect），放组件里要改两处且易漏；放 `loadYear` 则只改一处，并让**所有未来消费者**（国家搜索 / 详情 / 历史事件 / 3D 地球 / AI 查询）自动继承，同时保持「`loadYear` 是唯一数据入口」这条红线不变（仍然是同一个入口，只是出口做了纯后处理）。
- 缓存语义：缓存内即归一后数据；`applyGeographicOverlay` 幂等，故重复调用安全。

## §7 风险与限制

- **R1（本质限制）**：B 只让**显示**完整，`public/data/years/world_bc5000.json` 里依然没有南极；任何**绕过前端、直接读 JSON** 的消费者（未来 `server/` AI、3D 预计算、`data:relations`）仍会看到缺口。→ 记入 OPEN，将来按需上方案 A。
- **R2**：`entities.json` 仍含 `auto:antarctica`（years [1945,1960]）。将来做「国家搜索 / 国家详情」时若不套同一地理规则，列表里会出现一个叫 Antarctica 的政权。→ 届时在搜索层复用 `isAntarcticFeature` 过滤，或上方案 A。
- **R3**：纬度阈值是**有意为之的覆盖**：将来若上游给南极画成某个真实政权/条约多边形（如 Antarctic Treaty），也会被强制成中性灰。这符合「不作为历史政权」的需求，但会掩盖上游的政治表达，故在上游数据变更时需要复核。
- **R4**：注入用的是**冻结副本**。上游若改画南极海岸线，注入年（当前只有 −5000）会与自带南极的年份形状不同。→ 文档记录来源（`world_2010`），必要时重抽。
- **R5**：主 chunk 增加约 22 KB 原始 / 6–8 KB gzip（方案 B1）。若在意体积，可改 **B2**：把几何放 `public/data/geographic/antarctica.json`（`data:verify` 不扫多余文件，不会失败），仅在「缺南极」的年份按需 fetch（54 年中当前只有 1 年触发），代价是多一条异步路径与一个新增 public 资源。
- **R6**：`precision` 归一（3 → 1）会让 1945/1960 的南极填充透明度从 0.85 变为 0.55，与其余 52 年一致。若保留 3，这两年南极会明显更「实」。→ 决策点 D1。
- **R7**：`-5000` 新增要素 id=279，`public/data/relations/-5000.json` 无该 id 记录 → 该要素 tooltip 不显示关系行（正确，因为本就没有 resolved 关系）；`mousemove`/hover 仍正常（id 唯一）。
