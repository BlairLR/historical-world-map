## 3. 颜色是怎么绑定的

```
上游 NAME/SUBJECTO
  → normalizeKey()  8 条规则：nfc → trim → lower → 空格归一 → 连字符 → 引号 → 句点 → 标点
  → 手工别名表命中？ → 用 periods 判定 → 手工 entityId（如 CN-QING）
  → 否则全自动：
       按年份空档切分（连续缺失 ≥2 个快照即断代，只缺 1 个视为数据噪声）
       runIndex 0 → entityId = "auto:<key>"
       runIndex ≥1 → entityId = "auto:<key>#<n>"
  → hashInput：手工用 id 自身；自动 #0 用**代表拼写**（出现最多→最早→字典序）
               → 只要该 key 只有一种写法，哈希输入 === 改动前的输入
  → fnv1a → HSL → #rrggbb
  → 冻结进 data/identity/colors.json（只增不改，跨年/跨重跑稳定）
```

**颜色不能因为加载顺序变化**：AR5/AR6 已实测——连续两次全量构建，54 个年份文件 + `colors.json` + `entities.json` 共 **56 个文件 SHA-256 逐一相同**（合并哈希 `df9a28e2ad7b66421b58c5e212ca66ddff796a1fd5a12f146e8202baeccb4054`）。

**二次探测降冲突**：`assignColors()` 会避开 ①45° 邻域（15° 格 3×3）②与本实体共享任一 key 的其他实体 ③`aliases.succession` 里的更替对。实测只触发了 **1 次** 探测（`auto:england#2` `#7ebec6 → #74d091`），说明基底哈希已经够用。

## 6. ⚠️ 必须知道的副作用：5.98% 的要素换了颜色

逐要素比对「改动前 `colorForKey(SUBJECTO||NAME)`」与「改动后 `properties.color`」：

| 指标 | 数值 |
|---|---|
| 变色要素 | **1,042 / 17,438 = 5.98%** |
| 涉及 entityId | 200 个 |
| 其中年份含 2010 的（即会出现在"现代"地图上） | **80 个实体** |

这与设计文档 §3.2 的预测完全吻合（"只有被切分 key 的第 2/3 段 + 手工实体 + 2 个纯格式合并组会换色"）。构成：

1. **手工实体 21 个** —— 就是第 4 节那 8 处漂移修复 + 政权更替分色（预期内，是本次的目的）。
2. **被空档切分的 key 的第 2 段及以后**（`#runIndex ≥ 1`）—— 138 个 key 切出 178 个自动实体。
3. **2 个纯格式合并组** —— `Kwakwaka’wakw`/`Kwakwaka'wakw`、`Chinese Warlords`/`Chinese warlords`（P4.1 第 1 步的预测值，正是它俩）。

我按这个建议执行，**没有**自行决定哪些是假阳性——那属于历史判断，应该由你定。逃生口已经实现并可用：只需在 `data/identity/aliases.json` 的 `overrides.mergeRuns` 里加 key 字符串，重跑 `npm run data:build` 即可，无需改代码。

## 7. 已知局限（沿用设计文档 §11，未变）

1. **`BORDERPRECISION` 透明度分档未修** —— 同一个 hex 在不同年份因 `fill-opacity` 1→0.55 / 2→0.7 / 3→0.85 仍会呈现深浅差异。这是**另一个独立问题**（原分析里的成因②），本方案不含它。
2. **重叠绘制顺序未修** —— 1° 网格最多 11 个实体叠放，视觉颜色由叠加决定（成因③）。`entityId` 不改变绘制顺序。
3. **1,603 个实体只出现 1 年**（占 52%）—— 天然没有"跨年稳定"可言，是历史碎邦的正常形态。
4. **哈希撞色无法归零** —— 3,062 个实体用 2,480 种颜色，全局有 1,082 个实体处于撞色桶中；AR3/AR4 只保证"共享 key 的实体"和"45° 邻域"不撞色，不同窗口的同色是允许的。
5. **`periods` 是历史判断不是数据** —— `CN-ROC`/`CN-PRC` 的 1949 分界、`DE-FRG` 的双阶段，都是人工决定，写进了 `aliases.json` 并可被反驳。

## 8. 如何回滚

删掉 `data/identity/` 目录，把 `scripts/build-data.mjs`、`scripts/verify-data.mjs`、`src/data/types.ts` 三个文件恢复，重跑 `npm run data:build`。颜色会**精确回到**改动前的值（因为基底哈希算法 `fnv1a` + HSL 公式一行未改，只是输入从「原始 key」变成「实体代表拼写」）。`data/raw/` 全程只读，永远是原始素材。
