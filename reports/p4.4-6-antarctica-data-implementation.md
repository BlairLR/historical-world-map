## 2. 管线改动说明（行号级）

### 2.1 `scripts/build-data.mjs`

1. **配置**：新增 `GEO_DIR = data/geo`、`GEO_CONFIG_PATH = data/geo/geographic-entities.json`；启动期硬校验 `entityId === 'UNNAMED'`、`color === UNNAMED_COLOR`、`enforcePresence` 的实体必须有 asset、asset 必须是 `FeatureCollection` 且 `features.length >= 1`（任一不满足直接 throw）。
2. **D7 `--years` 护栏**：`--years` 会把 `manifest.snapshots` / `entities.json` 静默写成子集（`verify-data` 的单向断言抓不住，见 P4.4-5 §5），因此除显式 `--allow-subset` 外一律 throw。
3. **D6 `writeIfChanged(absPath, text)`**：内容相同则不写盘、返回 false。应用于**年份文件**与**颜色注册表**（`manifest.json` / `entities.json` 仍无条件写，因为它们的 `generatedAt` 等字段本就每次不同）。
4. **`convertFeature(f)`**：把原第 2 遍的逐要素循环抽成局部函数（`continue` → `return`，控制流与产物行为不变）；内部新增 `let minLat = Infinity` 逐点累加，得到 `isPolar = minLat <= poleLatitude` 与 `isGeographic = isPolar || [name, subject, PARTOF, ABBREVN].some(t => typeof t === 'string' && nameMatch.has(t.trim().toLowerCase()))`。
5. **R-B 身份归一**：身份块变为
   `if (isGeographic) { /* 保持 UNNAMED / #9aa0a6；不登记 usedEntityYears / usedEntityRawKeys；不计入 totalUnnamedKey */ } else if (rawKey && String(rawKey).trim()) { …原逻辑… } else { totalUnnamedKey++; }`
   —— 归一要素仅计入 `geographicFeatures`，因此它**不参与颜色演化**，也不会新增/保留 polity。
6. **R-A 存在性补全**：年份要素循环结束后，若 `polarFeatures === 0`，对每个 `enforcePresence` 实体调用 `convertFeature(asset.features[0])`；追加后校验 `features.length === before + 1`，否则 throw（资产几何量化后退化即失败）。
7. **D3 告警**：`polarFeatures > 1` 时 `console.warn` 并计入告警汇总（本轮实测 **0 条**）。
8. **日志**：逐年行追加 `⚑ R-A 补全地理实体 N`；汇总追加 `地理实体：登记 N 个 · 归一要素 N 个（归入 UNNAMED #9aa0a6） · R-A 补全年份 N 个（…）`。

### 2.2 `scripts/verify-data.mjs`（新增 AR10）

- 逐要素：算出要素自身 bbox 后 `isPolar = fb[1] <= geoPoleLatitude`；若 `isPolar` 或名称命中 `nameMatch`，则断言 `props.entityId === 'UNNAMED'` 且 `props.color === UNNAMED_COLOR`，否则 `AR10 失败`。
- 逐年份：`polarFeatures === 0` → `AR10 失败：<file> 没有任何极地要素（最南纬度 > −89.9）`。
- 汇总：`AR10 地理实体  南极洲几何 N / 54 个快照 · 极地要素合计 N（全部 UNNAMED #9aa0a6）`。
