## 1. Task 1 — 现有 relations validation 是否存在

**结论：已存在阻断式 schema 校验，但 `relationship ↔ sovereignId / authorityId` 的语义约束完全不存在。**

### 1.1 已存在的（`scripts/lib/relations.mjs`，全部是**阻断式**：返回 problems，非空即 `throw`）

| 函数 | 位置 | 校验内容 |
| --- | --- | --- |
| `validateRules(rules, options = {})` | `scripts/lib/relations.mjs:237` | output 字段白名单 / 禁用键、`sovereignId` 类型 + polity 注册表、`authorityId` 命名空间 + 注册表、relationship 枚举、`source` / `confidence` |

| `validateRelationRecord(record, options = {})` | `scripts/lib/relations.mjs:329` | 五字段闭集、`resolutionStatus` 闭集、authorityId 命名空间·注册表、sovereignId 注册表、§4.4.1 推论 1（`relationship ≠ unknown ⇒ resolved`，`:351-353`）、§4.4.1 推论 2（`unresolved ⇒ null + null + unknown`，`:354-356`） |

调用点（`scripts/lib/relations-build.mjs`）：`:91` / `:96`（`loadConfig` 内，problems 非空即 `throw`，`:98-100`）、`:196`（逐记录校验，problems 非空即 `throw`，`:197-199`）；另有覆盖度硬断言 R1/R2（`:241-246`）与记录字段集合断言（`:247-252`）。

### 1.2 缺口

- `validateRelationRecord` **只机器校验 §4.4.1 推论 1/2**（`scripts/lib/relations-build.mjs:487` 报告行自述），即只保证「resolved / unresolved 的字段形状」。
- **没有任何地方检查**「某个 relationship 是否允许 `sovereignId = null`」「是否要求 `authorityId` 非空」「`sovereign-territory` 的 sovereignId 是否等于自身 entityId」。
- 这正是 **OQ-C5 的张力**：P4.1-A v3 §7「`occupied` ⇒ `sovereignId` 非空」与 Batch 1 六条 `occupied` 记录的 `sovereignId: null` 并存，且 OQ-C5 在 `docs/design/P4.1-C-OQ-decisions.md` 中仍标 **OPEN**。

### 1.3 影响面检查（决定最小方案可实现）

- `tests/relations/run.mjs` 的 R4/R5 静态禁用词扫描**只读 `scripts/lib/relations.mjs`**（`tests/relations/run.mjs:183`）→ 新增文件不会触发该断言。
- `tests/relations/run.mjs` 对 stdout / stderr **无断言**（只 `JSON.parse` 读取产物），`buildRelations` 的 6 处调用（`:117`、`:448`、`:486-487`、`:519`、`:530`）均只取字段值 → 返回值新增一个字段不影响既有测试。
