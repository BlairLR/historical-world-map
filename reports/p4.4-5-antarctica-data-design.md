# P4.4-5 南极洲数据层补全 —— 设计 + 影响分析（只读阶段，未执行任何修改）

> 阶段性质：**只读设计与影响分析**。本文件是唯一产物；`data/`、`public/data/`、`src/`、`scripts/` 全部未改动。
> 上位要求（m05719，原文要点）：否决前一轮「展示层 overlay」方案；南极洲必须进入**快照数据本身**，不得在 `loadYear` / `MapView` 等前端运行时打补丁。
> 目标 6 条：① 修复公元前 5000 年南极洲缺失 ② 最终 54/54 年份快照都含南极洲 ③ 南极洲是固定**地理实体**、不作为政权参与颜色演化 ④ 1945/1960 的 `auto:antarctica` 归一为统一的南极洲地理实体 + 中性灰 ⑤ 缺失年份由**数据构建流程**自动补全（非前端追加）⑥ 未来新增年份若原始数据缺南极，同样自动补全。
> 必答 7 项：Q1 标准几何来源 / Q2 改 raw 还是 build 阶段通用规则 / Q3 重建哪些 `years/*.json` / Q4 manifest·entities.json·relations 是否同步更新 / Q5 113 个保护文件实际变化多少 / Q6 如何验证 54/54 一致 / Q7 如何避免误识别南极附近岛屿。

## 0. 结论摘要

**推荐方案（数据层，管线内建）**：

1. 新建**项目自有**的规范南极几何资产 `data/geo/antarctica.geojson`（从上游 `data/raw/geojson/world_bc4000.geojson` 的 `features[6]` **逐字**复制，保留上游 7 个属性键，坐标未量化、`BORDERPRECISION: 1`）。
2. 在 `scripts/build-data.mjs` 第 2 遍（写出遍）加入两条**通用规则**：
   - **R-A 存在性补全**：某年待写出的要素里若**没有任何「极地要素」**（自身 bbox `minY ≤ −89.9`），则把规范南极几何**追加**为该年最后一个 feature（`id = features.length`），完全走与上游要素相同的量化 / 属性瘦身 / 身份路径。
   - **R-B 身份归一**：任何被判定为「南极洲」的要素（极地判定 `minY ≤ −89.9`，**或** `name` / `subject` / `partOf` / `abbrev` 去空白小写后**精确等于** `antarctica`）**跳过政权身份解析**，强制 `entityId = 'UNNAMED'`、`color = '#9aa0a6'`，其余字段（几何 / name / precision 等）原样保留。
3. 在 `scripts/verify-data.mjs` 增加 **AR10**：逐快照断言「至少 1 个极地要素，且所有极地要素都是 `UNNAMED` + `#9aa0a6`」→ 把「54/54」变成**构建期硬门**（未来年份缺南极会直接让 `npm run data:verify` 失败）。

**为什么这个方案满足全部 6 条目标**：R-A 让缺失年份在**快照文件里**就有南极（目标 ①⑤⑥）；R-B 让南极永远是 `UNNAMED`/中性灰、不进 `entities.json`、不占颜色（目标 ③④）；规范几何来自上游、由构建确定性量化，54 年的南极形状**逐字节统一**（目标 ②）。

**影响规模（精确预测，见 §6/§7）**：54 个年份文件中**只有 3 个**内容改变（`world_bc5000.json` +1 要素、`world_1945.json` / `world_1960.json` 各 2 个属性字段），另有 `entities.json`（3,056 → 3,055 条）与 `manifest.json` 变化；113 个保护文件中**内容变化 5 个**，其余 51 个年份文件与 `data/identity/colors.json` 仅因「被重写」而 mtime 变化（字节不变），`data/raw/**` 55 个 + `aliases.json` 共 56 个**完全不动**。前端 `src/**` **0 改动**。

## 2. Q1 —— 标准南极 geometry 从哪个现有快照提取

**答案：从 `data/raw/geojson/world_bc4000.geojson` 的 `features[6]` 提取**（保留上游 7 个属性键 + 未量化坐标，逐字复制）。

选择理由：

1. **是"上游输入"而不是"派生产物"**：注入的要素因此和上游要素走**完全相同的代码路径**（`quantizeRing` → 属性瘦身 → 身份解析），不需要在管线里开第二条几何处理分支。
2. **与缺陷年份同时代、同精度**：−4000 紧邻缺失的 −5000，且 `BORDERPRECISION = 1`（−5000 自身要素也都是 precision 1）→ 注入后 −5000 的南极配色/透明度与其时代风格一致。
3. **几何就是"多数派"形态**：−4000 的南极与 45 个年份的南极几何**逐字节相同**（形态 A），不是 1878/1880/1900 的 721 顶点简化形，也不是 −1..400 的 1,016 顶点古典形。
4. **可复算**：构建确认过 (P4.4-2) 当前产物可由上游逐字节重建，因此"上游 −4000 → 量化后 −4000 产物"这条映射是确定的 → 注入 −5000 得到的就是**同一份几何**（部署后用 `deep-equal` 断言，见 §8.3）。
5. 等价的备选来源（几何逐字节相同，可任选）：`world_bc8000.geojson` / `world_bc10000.geojson` / 任一形态 A 年份的上游文件（如 `world_1600.geojson`）。**不选** 2010（`precision 3`）与 1878/1880/1900（721 顶点简化形）。

**不采用的替代做法**：
- ✗ 直接嵌入 `build-data.mjs` 源码（1,091 个坐标点写进脚本，不可审查、不可替换）。
- ✗ 运行时从 `public/data/years/*.json`（派生产物）里"就近取一份"→ 让生产数据的来源依赖另一个生产产物，重建顺序会互相耦合。
- ✗ 让构建"自动挑选顶点最多的南极要素"→ 上游改动会让补全几何静默漂移，不可复现。

## 3. Q2 —— 改 raw 数据，还是 build 阶段建通用补全规则

**答案：在 `scripts/build-data.mjs` 建通用补全规则，`data/raw/**` 一个字节都不改。**

| 维度 | 改 raw（`data/raw/geojson/world_bc5000.geojson` 里塞一份南极） | **build 阶段通用规则（推荐）** |
|---|---|---|
| 保护集影响 | 命中 `data/raw/**`（113 个保护文件里的 55 个之一）→ 直接改动保护文件 | `data/raw/**` **0 改动**（55 个文件不动） |
| 可重取性 | `npm run data:fetch` 会**静默覆盖**，修复消失 | 修复属于项目代码，重取上游后依然生效 |
| 覆盖范围 | 只修 −5000（目标 ①） | 所有缺失年份（目标 ⑤）**+ 未来新增年份**（目标 ⑥） |
| 上游戏一致性 | 破坏"raw = 上游镜像"的不变量，无法再区分"上游如此"与"我们改过" | 上游镜像保持纯净，修正量记录在项目自有资产 + 代码里 |
| 许可/来源 | 直接改 GPL-3.0 上游数据副本，provenance 混乱 | 资产文件带 `_provenance`（来源文件、要素下标、提取日期、几何 SHA-256） |
| 可测试性 | 只能在数据里看一眼 | 可用 AR10 变成构建期硬门（可回归） |

**规则的两个层次（供裁定，见 §12 D1）**：

- **G1（推荐）配置驱动**：新增 `data/geo/geographic-entities.json`（例如 `{"version":1,"entities":[{"id":"antarctica","asset":"data/geo/antarctica.geojson","poleLatitude":-89.9,"names":["antarctica"],"describe":"南极洲：固定地理实体，不参与政权颜色演化"}]}`），`build-data.mjs` 读它 → 未来要把"冰盖/大洋"等地物做成同机制只加配置。代码增量约 +35 行。
- **G2 单例硬编码**：只写南极一条规则（`const ANTARCTIC = {...}`），代码增量约 +20 行。更小，但下一个固定地物需要再改脚本。

两者**行为完全一致**，差别只在扩展成本；下面 §4 按 G1 描述（G2 是其子集）。

## 4. 设计详述（规则、插入点、资产格式）

### 4.1 新增资产：`data/geo/antarctica.geojson`

```jsonc
{
  "type": "FeatureCollection",
  "_provenance": {
    "note": "南极洲规范几何（固定地理实体，非政权）。由 scripts 一次性从上游客积复制，之后手工维护；构建期只读。",
    "extractedFrom": "data/raw/geojson/world_bc4000.geojson",
    "featureIndex": 6,
    "extractedAt": "<实施当天 ISO 时间>",
    "rawGeometrySha256": "ec8bdbbe4fd033cc…",
    "reason": "world_bc5000 的上游数据没有南极几何，且需为未来年份提供统一形状",
    "upstream": "aourednik/historical-basemaps@master (GPL-3.0)"
  },
  "features": [
    { "type": "Feature",
      "properties": { "NAME": null, "ABBREVN": null, "type": null, "weblnks": null,
                      "SUBJECTO": null, "BORDERPRECISION": 1, "PARTOF": null },
      "geometry": { "type": "MultiPolygon", "coordinates": [ /* 上游原始坐标，未量化 */ ] } }
  ]
}
```

要点：
- 放在 `data/geo/`（**不在** `data/raw/**` 也不在 `data/identity/**`）→ 不属 113 个保护文件，也不会被 `data:fetch` 覆盖。
- 属性保持**上游原样**（`NAME`/`SUBJECTO` 为 `null`）→ 注入后自动成为 `UNNAMED` + `#9aa0a6`。
- 坐标**不预量化**：由构建统一量化，结果与其它 45 年逐字节相同（1,092 → 1,091 顶点）。
- 附带 `rawGeometrySha256`，便于日后校验资产没被误改。
- 提取命令（实施阶段执行，一次性，脚本用完即删）：
  ```js
  // 读 data/raw/geojson/world_bc4000.geojson → 取 bbox.minY<=-89.9 的唯一要素
  // → 原样写入 data/geo/antarctica.geojson（连同 _provenance）
  ```

### 4.2 规则 R-A：存在性补全（写进 `build-data.mjs` 第 2 遍）

插入点：`scripts/build-data.mjs:335-477` 的「逐年份」循环内。

1. 年份循环开始处新增 `let hasPolar = false;`。
2. 逐要素循环内（现有 bbox 累加三循环 `:380-389` 旁）累加该要素自身的 `minY`；若 `minY <= poleLatitude`（−89.9）则 `hasPolar = true;`。
3. 逐要素循环结束后（`:436` 之后、`:438` 构造 `fc` 之前）：
   ```js
   if (!hasPolar) {
     const injected = convertFeature(geoAsset.features[0], features.length); // 走同一套量化/瘦身/身份路径
     if (!injected) throw new Error(`${year}：规范南极几何退化，补全失败`);
     features.push(injected);
     hasPolar = true;              // 断言用
     geographicInjected++;         // 统计用
   }
   if (!hasPolar) throw new Error(`${year}：补全后仍无南极要素`);
   ```
4. 为了"走同一套路径"，把现有 `:346-434`（几何量化 + bbox 累加 + 顶点计数 + 属性装配 + 身份块）抽成一个局部函数 `convertFeature(rawFeature, id)`，**行为保持不变**——这一点由 §8.2 的"51 个年份文件逐字节不变"回归证明。

> 实现细节：`vertices` / `unnamed` / `colorsInFile` / 文件级 `bbox` 的累加必须包含注入要素（因此把统计逻辑放进 `convertFeature` 内或在其后统一更新）；注入要素的 `id = features.length`（追加到末尾）→ **−5000 现有 279 个 feature 的 id 0..278 全部不变**，sidecar 既有记录继续有效。

### 4.3 规则 R-B：身份归一（写进身份块 `scripts/build-data.mjs:393-419`）

在 `let entityId = UNNAMED_ENTITY; let color = UNNAMED_COLOR;` 之后、`if (rawKey && …)` 之前插入：

```js
  geographicFeatures++;
```

- **精确等于**（不是包含 `antarct`）：避免把 "French Southern and Antarctic Lands"（亚南极群岛领地）这类政权误判为南极大陆。
- `entityId` / `color` 保持初值 `UNNAMED` / `#9aa0a6`；`name`/`abbrev`/`subject`/`partOf`/`precision`/几何**一律不动** → 1945/1960 只改 2 个字段。

### 4.4 规则 R-C：构建期自检（写进 `scripts/verify-data.mjs`，新增 AR10）


## 5. Q3 —— 需要重建哪些 `years/*.json`

**答案：必须做一次「全量重建」（`npm run data:build`，不带 `--years`）——54 个年份文件都会被写一遍；但只有 3 个内容真的改变。**

不能只重建受影响年份，原因是**设计的硬约束**（`scripts/build-data.mjs` 实测）：

| 位置 | 事实 | 后果 |
|---|---|---|
| `scripts/build-data.mjs:112-132` | `--years a,b,c` 会**缩小 `years`**（"要写出的年份"） | 只有子集年份文件被写 |
| `scripts/build-data.mjs:456-465` | `snapshots[]` **只收集本次写出的年份** | `manifest.snapshots` 变成子集（丢 53 条） |
| `scripts/build-data.mjs:496-514` | `entities.json` 由本次运行的 `usedEntityYears` 派生 | `entities.json` 只含子集实体 |
| `scripts/verify-data.mjs:249-252` | 只断言 `manifest.allYears ⊇ 各快照年份`（**单向**） | 子集 manifest **不会**被 `data:verify` 抓住 → 静默损坏 |

## 9. Q7 —— 如何避免误识别南极附近岛屿

**答案：用"含南极点"的几何判据（`minY ≤ −89.9`）+「名称精确等于 `antarctica`」，绝不用纬度带（如 `minY ≤ −60`）。** 实测依据：

| 判据 | 命中要素（全库） | 误判风险 |
|---|---|---|
| `minY ≤ −89.9`（**采用**） | 53 个年份各 **恰好 1 个**大陆；−5000 为 0 | **无误判**：最"南"的非南极要素是智利 `−56.06769`（1920–2010）与阿根廷/无名要素 `−55.07004` → 判据与最近反例相距 **33.9°** |
| `minY ≤ −60`（**否弃**） | 除大陆外还会命中 **−1/100/200/300/400 的 5 个亚南极岛屿**（`−72.74946 / −72.67219 / −77.09835 / −80.94006 / −79.97419`，各 6~30 顶点） | 与最近反例仅 **3.9°** 余量；今天这些岛屿恰好已是 `UNNAMED` 灰（视觉无害），但**一旦上游给它们任何政权 key，就会被错误地"归一成南极"** |
| 名称包含 `antarct` | 只有 800/900/1815/1945/1960 五个大陆要素 | 若用**子串**匹配，未来出现 "French Southern and Antarctic Lands" 之类政权会被误判 → **因此用去空白小写后的精确相等** |
| 名称精确等于 `antarctica`（**采用**，与极地判据取并集） | 同上 5 个 | 无误判；作为几何判据的补充网（万一某年上游把南极画成不含极点的多边形，也不会被当成政权） |

附加护栏：

1. **存在性判据与身份判据共用同一信号**（极地 ∨ 名称）→ 不会出现"上游有一份不含极点的南极、补全规则又追加一份"的重复南极。
2. **亚南极岛屿按设计不动**（它们既不是"南极大陆"，也没有政权 key）→ 明确写入设计的"有意不覆盖"清单（§12 D4）。
3. AR10 只检查**极地要素**必须是 `UNNAMED`/灰，不对 `minY ∈ (−90, −60]` 的要素做任何断言 → 岛屿保持现状。
4. 若未来某年出现**两个以上**极地要素，AR10 目前只断言 `≥1`，但构建日志会打印每年极地要素计数；可在 D3 选择"多于 1 个即告警"。
